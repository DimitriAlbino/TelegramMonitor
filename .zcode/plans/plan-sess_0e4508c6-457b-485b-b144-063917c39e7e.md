# Three improvements: UI redesign, public status page, redirect handling

## 1. UI redesign — modern, responsive, dark/light toggle

**Approach**: extend the existing vanilla-CSS + CSS-variable system (no build step, no framework). The `:root` variables are already the design-token layer — add a `[data-theme="light"]` override set, responsive `@media` queries, and a theme toggle.

**Changes:**
- **`static/style.css`** — rewrite/extend:
  - Add `[data-theme="light"]` variable overrides (light bg, surfaces, text, border; retune the rgba badge/flash tints for light backgrounds).
  - Add `@media (max-width: 640px)` breakpoints: collapse `.form-row` to 1 column, make tables horizontally scrollable (`.table-wrap` wrapper), wrap/hamburger the nav, stack the dashboard header.
  - Polish: better spacing, rounded cards, subtle shadows, consistent button styles, sticky nav.
  - Fix the double-flash quirk (remove per-template flash rendering; let `base.html` own it).
- **`templates/base.html`**:
  - Add a theme-toggle button (🌙/☀️) in the nav, before the user email.
  - Add a small inline `<script>` in `<head>` that reads `localStorage.theme` *before paint* (no FOUC) and sets `document.documentElement.dataset.theme`. Default to `prefers-color-scheme` on first visit.
  - Add a `{% block scripts %}` at the end of `<body>` for per-page JS.
  - Remove inline styles; move them to CSS classes.
- **All templates** (`dashboard.html`, `monitor_detail.html`, `monitor_form.html`, `settings.html`, `status_page.html`, `link_telegram.html`, `login.html`, `signup.html`, `verify.html`, `reset_*.html`):
  - Replace inline `style="..."` attributes with proper CSS classes.
  - Remove redundant flash rendering (base.html handles it).
  - Wire the `min_interval` context var that `monitor_form.html` references but routes don't pass.
- **Theme persistence**: `localStorage` (browser-local), not DB. A display preference doesn't need an account setting. Initial default respects `prefers-color-scheme`.

## 2. Public status page — human-readable HTML

**Approach**: render an HTML page at `GET /status/{slug}` (the natural URL for a "page"). Keep JSON available at `?format=json` for API consumers.

**Changes:**
- **New template `templates/public_status.html`**: a standalone page (own `<html>`, not extending `base.html` — it's public, no nav). Shows:
  - Title + subtitle from the StatusPage config.
  - Overall summary badge: "All systems operational" (green) or "X of Y monitors down" (red).
  - Per-monitor cards: name, state badge (up/down/unknown), last latency, last checked time, target.
  - Incident history: recent incidents with open/close times + duration.
  - Responsive, themed (dark/light toggle works here too — same CSS + localStorage).
  - Auto-refresh meta tag (every 60s, matching the cache TTL).
- **`tgmonitor/api/statuspage.py`**: `public_status_page` handler — if `?format=json` or `Accept: application/json`, return the existing JSON; otherwise render the HTML template via `Jinja2Templates`. Keep the `Cache-Control: public, max-age=60` header on both.

## 3. HTTP redirect handling — per-monitor "Follow redirects" checkbox

**Approach**: add a `follow_redirects: bool` config option. When enabled, httpx follows 3xx redirects to the final URL and checks *that* response — so `mappafacile.it` → 301 → `www.mappafacile.it` → 200 → success. This is more useful than "treat 3xx as success" because it validates the actual destination.

**Changes (7 files, all additive):**
- **`tgmonitor/executors/base.py`**: add `follow_redirects: bool = False` to `CheckConfig`; add `follow_redirects: bool = False` kwarg to the `Transport.request` protocol.
- **`tgmonitor/executors/http.py`**: `HttpTransport.request` passes `follow_redirects` to `client.get(url, follow_redirects=...)`. `run_http_check` threads it from `config.follow_redirects`.
- **`tgmonitor/worker/engine.py`**: add `follow_redirects` to `ClaimedMonitor` + `to_check_config()`; read `COALESCE((config->>'follow_redirects')::bool, false)` in `CLAIM_DUE_SQL`.
- **`tgmonitor/api/monitors.py`**: add `follow_redirects` to `MonitorBase`/`MonitorUpdate` Pydantic models, `_build_config`, and the `config_keys` merge set.
- **`tgmonitor/ui/app_routes.py`**: add `follow_redirects: bool = Form(False)` to create + edit handlers; store in the config dict.
- **`templates/monitor_form.html`**: add a checkbox "Follow redirects (accept 301/302)" in the HTTP-specific fields block.
- **`tests/conftest.py`**: update `FakeTransport.request` signature to accept `follow_redirects` (no-op default).

**Default**: unchecked (follows current behaviour — strict expected-status check on the raw response).
